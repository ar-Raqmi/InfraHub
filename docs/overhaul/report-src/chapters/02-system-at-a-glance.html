The system at a glance

One site, eight pages, one big form

How the parts of InfraHub connect, from the page in your browser to the row in the database, and where the weight of the code sits.

Stack

React 19 + Vite, Hono on Cloudflare Pages, D1 and R2. ~25,500 lines of TypeScript, no tests. Verified

vite.config.ts:31-41 · wrangler.toml

Think of InfraHub as two halves joined by one cable. In the browser, each HTML page boots a React app that asks apiService for data and draws the screens; it also builds every PDF itself. On Cloudflare, a small Hono API reads and writes eight tables. The heavy things, such as each project’s BQ, are stored as JSON documents inside a single projects row, not as tables of their own.

The “year” is a URL setting, not a field

Projects are not stored with a year. Each page filters the full list by the year of Tarikh Buka, and that year also picks the settings row (companies, votes, sebutharga). Four projects opened in Dec 2025 therefore sit in the 2025 bucket. Verified

Things that look alive but are not

No offline/PWA (the service worker removes itself), no realtime (a mock that always says “subscribed”), a notifications table nobody reads, and 8 unused dependencies. Verified

Where the code lives

Half the code is in sixteen page files

The pages/ folder holds 13,335 lines, more than everything else combined. Five files are over 1,500 lines. The form that runs the whole workflow, ProjectDetail.tsx, is one of them, and the two BQ editors are near-copies of each other: 588 of the 1,085 non-trivial lines of the first appear word for word in the second. Inside the projects row

The BQ is a document, not a table

Each project keeps its BQ as one JSON document: a list of bills (groups), each with header, item and note rows. Every item row carries its own copy of description, unit and rate, plus three ids pointing back to the library item it came from. That id is the only link to the Pustaka. Verified

This is why a cross-project question such as “how many metres of longkang did we build this year” is hard today: the answer is spread across 489 documents that must each be opened and parsed. Inference
