What it built

Nothing a user could see. F made the parts every other builder stands on: ten new tables, the rules as pure TypeScript, an Excel reader and the routes that serve them.

  • Migrations. 0001 adds contracts, companies, contract_companies, rate_book_versions, rate_book_groups, rate_book_matches, change_log, app_config, lookup_values and policy_rules. 0002 adds the contract and book version to every project.
  • Domain layer. The money rules lifted out of the 1,790-line project form; a policy that answers “which value applied on this date”; the master-BQ parser, matcher, diff, row status and re-price planner.
  • Excel reader. SheetJS CE 0.20.3 turns a file into rows in the browser and keeps a code like 1.10 as text.
  • API. 11 new files: contracts, rate book, change log, config, lookups, policies, a legacy migration, and the project swap and re-price routes. API.md has the route table and 35 curl examples.
  • Client layer. One method per route in apiService, four hooks, and the acting user sent as a header.

Why no screen?

The contract (chapter 02) fixed the API before any screen existed. With routes and rules in place, K, P1, P2 and O could each build a screen at once. F marked API.md “FOUNDATION READY” when the routes were done.

One deviation from the contract

rate_book_groups has two extra columns, code and bill, so an item’s official number and bill heading survive storage. It is additive; nothing in CONTRACT.md §3 was removed.

How the importer reads the officer’s Excel

A script reads every rate and unit from its cell. It never asks an AI. Matching only suggests which old item a reworded line is, and a person decides.

  • 3 rows are off the pattern. The kontraktor rate is normally 0.849 to 0.851 of the jabatan rate. Three rows differ (lowest 0.8244, item 11/4.3(xiii)). The importer copies cells as written, so that is the file’s data.
