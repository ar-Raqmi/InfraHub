What it built

The header

  • Contract panel. Code, status, “Kadar versi N”, and when locked, why: “Dikunci: No. Inden … telah dikeluarkan”.
  • Stepper. The six statuses, with the four phase tabs laid under the statuses they cover. On a phone it folds to one line.
  • No. Sebutharga is read-only now: the contract decides it, and “Tukar sebutharga” is how to change it.
  • Both BQ editors read the project’s book. Tambah Item, templates and pelarasan additions come from the project’s sebutharga, not the global Pustaka.
  • Money rules moved out. LAD, LoC, kos sebenar and pelarasan extra now call domain/money with policies from Tetapan. The cost bar moved into its own file.
  • Stale rows are flagged with an indicator the officer decides on (page 3 of this chapter), never rewritten on their own.
  • The BQ PDF prints one line under RINGKASAN: “Kadar: Jadual Kadar Harga MPS/SH/302/25 (versi 1)”, checked with pdftotext.

Swap and re-price

The spec’s arithmetic

before   2,295.00
change   3 x 12.50 = 37.50
after    2,332.50

The spec asserts that the preview differs from the old total by exactly quantity times rate change, then that Apply stores that same total as kos projek.

  • Locked projects can preview; only apply is held.
  • Unlocking is a separate, logged call (swap-unlocked).

Stale rows: an indicator, never a silent rewrite

Rules behind the screens

  • Indicators show on draf projects only (owner decision 4), and only in the BQ Kontrak editor.
  • Four states exist: OK, KADAR_BERUBAH, PERKATAAN_BERUBAH (wording or unit only) and TIADA (gone from the book). Only the first rate-change state was driven in a browser.
  • Templates resolve by stable item id. A row whose source is not in the book is kept, flagged TIADA and listed, never dropped.
  • The editors read the contract’s current published book, not the project’s stored version.
