Six rules that kept them apart

  1. One worktree each. Every builder had its own checkout and branch, so no two edited the same file at the same time.
  2. One contract. CONTRACT.md fixes the tables, API, domain modules, colours and who owns which file. Anything else is a request in NEEDS-lead.md.
  3. Production is off limits. The local wrangler.toml points at a fake database id. Builders import the anonymised seed into their own state.
  4. Prove it, don’t say it. F wrote its tests first and kept the red runs. Wave-2 builders each wrote a scripted browser spec.
  5. A report contract. Each builder writes PROGRESS and REPORT files with raw command output; the sections are fixed: Done, Evidence, Verified vs unverified, Caveats.
  6. The lead merges and re-runs. Builders see only their own part; the cross-cutting faults appear after merging (chapter 10, p. {{page:10}}).

How to read these numbers

The dollar figures are a yardstick: what the same tokens would cost at list price. The plan quota moved from 9 to 72 % of a session and from 5 to 13 % of a week. Chapter 12, p. {{page:12}} covers tokens, process and what went wrong and was caught.

The method in one line

Write the contract first, give each builder one slice, make every builder prove its slice with a script that can fail, then merge one at a time and re-run it all on the merged code.
