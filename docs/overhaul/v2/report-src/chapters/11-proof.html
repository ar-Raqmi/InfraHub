Isolation: production was never in the path

A branch preview of infra-hub would have bound the production D1 and R2: its wrangler.toml has no [env.preview]. So the preview is a separate Pages project with its own D1 (infrahub-v2-preview-db) and R2 (infrahub-v2-preview-bucket). The deploy script refuses any name without v2-preview and refuses the production database id.

How to run the proof again

Four commands, in order. The specs create their own data and delete it. They log in as admin01 or pja01; the password is read from line 2 of ~/Documents/InfraHub-backups/dev-seed/CREDS.txt and never printed.

# 1 the gate (repo root) npx vitest run && npx tsc --noEmit && npm run build # 2 a local server on a throw-away state (worktree with the fake database id) bash docs/overhaul/v2/tools/bootstrap-local.sh <state-dir> npm run build && npx wrangler pages dev dist --port 8790 --persist-to <state-dir> --compatibility-date=2026-06-18 then once: POST /api/v2/admin/migrate-legacy # 3 the four specs, local and then the preview (Playwright for Python) for s in O K P1 P2; do python docs/overhaul/v2/e2e/$s.spec.py --base http://localhost:8790; done for s in O K P1 P2; do python docs/overhaul/v2/e2e/$s.spec.py --base https://infrahub-v2-preview.pages.dev; done # 4 money parity: the header of docs/overhaul/v2/e2e/P2-money-parity.ts has the exact vite build + node line

Inference What this proof does not cover
